Getting Bee Into Claude

The Connector Kept Failing. The Fix Was To Skip It.

If a tool you installed keeps refusing to connect, this one's for you.

I wear a Bee. It's a small wearable that records my conversations, and it catches things I forget by dinner: ideas, promises, things I told someone I'd do.

Claude couldn't see ANY of it.

The only door was a Google Drive folder. Claude can read that folder. So I moved each Bee file into it by hand.

I wanted Bee straight into Claude. No folder. No carrying.

What I Tried First

Bee has its own official tool. You turn on Developer Mode in the app, install the tool on your Mac, log in, and run one command that adds Bee to Claude.

It installed. It logged in. Claude showed a Bee extension, switched on.

Then, on that same screen, in red: "Bee couldn't start."

The Tests

So we tested. Claude and I, with me running each command on my Mac and telling it what I saw.

Was it the version of Node on my Mac? No.

Was the program in the wrong place? No.

Did it need a different set of settings around it? No.

Did it fail when Claude first said hello to it? No. I said hello myself, from Terminal. It answered, and handed back its list of tools.

EVERY test I could run on my own Mac passed.

The Turn

Bee's program was FINE. Run by hand, it worked every time.

The only thing failing was the part in the middle: the connector Claude uses to start it.

The Lesson

The far more certain way to connect Bee is NOT to fix the connector that keeps failing. It's to go around the connector.

I had two choices:

1. Keep hunting for why the connector won't start. I had no lead left.

2. Skip the connector. Tell Claude to start Bee's program itself.

What I Did

I took option 2. I added one entry to Claude Desktop's settings file that points straight at Bee's program.

I restarted Claude. Bee showed up. I checked it.

It was working. Bee, inside Claude. No folder. No carrying.

Where It Didn't Hold

This is for a Mac with an Apple chip, because the address of Bee's program says "mac-arm64." I haven't tried other computers.

If you move or reinstall Bee's tool, that path changes and the entry has to change with it.

Somewhere in the middle I also updated the Claude Desktop app. I can't say for certain it played no part.

Remember This

When a connector keeps failing and the program works on its own, don't fix the connector. Go around it.

Mine was a connector that wouldn't start. What's yours?

The Steps

You do these on your own Mac and phone. Nothing here needs a password or a key typed into Claude. Terminal is a text window on your Mac: press Command and Space, type Terminal, press Return. You type a command, press Return, and it answers. Every command below works that way.

  1. Turn on Developer Mode. In the Bee app on your phone, open Settings and tap the Version line five times. You'll see "Developer Mode enabled."
  2. Install Node. Go to nodejs.org, download the LTS installer, and click through it. Then quit Terminal (Command and Q) and open it again. Type node --version and press Return. You should see a number.
  3. Give yourself a tools folder. This skips a red "permission denied" error I hit on the next step. Paste all four lines together, then press Return.
    mkdir -p ~/.npm-global
npm config set prefix ~/.npm-global
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
  4. Install Bee's tool. Type npm install -g @beeai/cli and press Return. Then type bee version and press Return. You should see a number.
  5. Log in. Type bee login and press Return. Approve it in the Bee app on your phone. Keep the link it shows to yourself. Then type bee status. You should see "Verified" and your name.
  6. Try the easy way first. Type bee mcp connect claude and press Return, then click Install in Claude Desktop. If Bee works, stop here. If it shows "Bee couldn't start," go on.
  7. Find the address of Bee's program. Type bee mcp status and press Return. Find the line that starts with "Command:". Copy everything after "Command:", up to but not including the words "mcp serve". That long path is the address.
  8. Prove the program is fine. Type bee mcp serve and press Return. It should sit there and say nothing. That's healthy. Press Control and C together to stop it.
  9. Add the direct entry. In Claude Desktop, open Settings, then Developer, then Edit Config. That opens the settings file. If it's empty or just {}, replace it with the block below. Paste it, don't retype it, and put the address from step 7 where it says so.
    {
  "mcpServers": {
    "bee-direct": {
      "command": "PASTE THE ADDRESS FROM STEP 7 HERE",
      "args": ["mcp", "serve"]
    }
  }
}
    If the file already has an mcpServers section, add the bee-direct entry inside it, with a comma between entries. Save it.
  10. Restart and test. Quit Claude completely (Command and Q) and open it again. In a new chat, type: "Use Bee to check whether you're signed in." That check reads none of your conversations.

If it breaks later. Type bee status. If it says you're signed out, run bee login again. The first time Claude really reads Bee, your Mac may show a Keychain pop-up. Read it before you click. If Claude shows "Failed" after an update, check that the address in step 9 still matches bee mcp status.

The rule I gave it. Claude reads Bee only when I ask, only the business conversations, and never changes anything in Bee. Claude follows that rule. Nothing technical forces it.
